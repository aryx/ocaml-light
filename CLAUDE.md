# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ocaml-light is a fork of OCaml 1.07 (Caml Special Light era) with objects and
functors stripped out, maintained for educational purposes. It is a
self-hosting compiler: the tree contains both the compiler sources
(bytecode + native-code compilers) and the bootstrap binaries used to build
them from scratch. It also has a Plan 9 port (used by the sibling
`xix`/`principia-softwarica` projects) and a `dune` build used only for
editor tooling (merlin), not for the real build.

## Build

The real build is GNU Make, not dune. `dune` is only for IDE support (see below).

```sh
./configure          # generates Makefile, config/m.h, config/s.h from config/*-templ
make coldstart        # bootstrap the very first bytecode compiler from boot/
make world             # full build: runtime, ocamlc, ocamllex, ocamlyacc, stdlib, ocaml toplevel
make bootstrap          # recompile everything with the just-built compiler, checked against boot/ for a fixpoint (run twice if the first pass doesn't converge)
make opt                  # native-code compiler (ocamlopt) and opt-compiled stdlib
make ocamlc.opt              # optional: native-code version of ocamlc
make ocamlopt.opt               # optional: native-code version of ocamlopt
make install                       # install into the configured bindir/libdir
```

`make clean` / `make partialclean` clean build artifacts; `make cleanboot`
resets `boot/` (rarely needed — only when re-bootstrapping from scratch).

Docker builds (used in CI, also handy for a clean local build) — see
`Dockerfile` targets `bytecode` / `native-x86_64` and `Dockerfile.plan9`:

```sh
make build-docker        # bytecode
make build-docker-opt    # native x86_64/aarch64
make build-docker-plan9  # cross-compiled for Plan 9 via goken + principia-softwarica
```

Nix: `shell.nix` + `nix-shell --pure`, then the same `configure`/`make coldstart`/`make world`/`make opt` sequence (see `.github/workflows/nix.yml`).

### dune (editor tooling only)

`dune-project`/`dune` exist purely so merlin/editors get code navigation; it
does **not** produce the real `ocamlc`/`ocamlopt`. It needs generated files
(`parser.ml`, `utils/config.ml`, etc.) produced by `make` first:

```sh
make build-dune   # runs make, then `dune build`
make clean-dune   # dune clean
```

## Tests

```sh
make test          # builds everything, then runs make in each of: tests examples testasmcomp test otherlibs/num/test
```

Each test directory has its own `Makefile` invoked with the freshly built
compiler (e.g. `test/Makefile` compiles `test/*.ml` benchmarks with
`../ocamlc`/`../ocamlopt` and runs them). There is no single-test runner —
to run one test directly, `cd` into its directory and build the corresponding
target by hand (e.g. `cd test && make fib.byt && ./fib.byt`).

## Linting

```sh
make check   # osemgrep --experimental --config semgrep.jsonnet --strict --error
```

Rules live in `semgrep.jsonnet` (imports `p/ocaml` plus a couple of local
rules); CI runs the same command (`.github/workflows/semgrep.yml`).

## Architecture

Standard OCaml compiler pipeline, one directory per stage — this mirrors
upstream OCaml's own layout (minus objects/functors):

```
parsing/   lexer, ocamlyacc grammar (parser.mly), parsetree, source locations
typing/    type inference/checking: env, ctype (unification), typecore, typedecl, typemod
bytecomp/  parsetree/typedtree -> lambda -> bytecode instructions (instruct, bytegen, emitcode)
asmcomp/   lambda -> cmm -> mach -> linearized asm; per-arch backends in asmcomp/{i386,arm,mips}/
driver/    ties parsing+typing+bytecomp (or +asmcomp) together into ocamlc/ocamlopt main()
utils/     shared low-level helpers (config, misc, clflags, tbl)
```

Runtime systems (C, not OCaml):

```
byterun/   bytecode interpreter + GC + runtime (interp.c, gc_ctrl.c, ...) -> ocamlrun
asmrun/    native-code runtime support (GC, exceptions, stack walking for compiled code)
```

Other pieces:

```
boot/          pre-built bootstrap ocamlrun/ocamlc/ocamllex/ocamlyacc + stdlib .cmi used to build the first coldstart compiler
stdlib/        the OCaml standard library sources, compiled with the freshly-built compiler
lex/, yacc/    ocamllex and ocamlyacc, the lexer/parser generator tools (self-hosted)
otherlibs/     optional libraries: unix, threads (+ systhreads), str, num, graph (X11), dbm, dynlink
tools/         ocamldep, ocamlprof, developer tools, plus tools/toplevel/ (the `ocaml` REPL driver)
config/        autoconf-style templates (m.h/s.h/Makefile generated by ./configure from *-templ files); config/plan9.h is the Plan 9 target config (copied over s.h manually, see Dockerfile.plan9)
```

Build order dependency: `boot/` (pre-built) bootstraps a first `ocamlc`,
which builds `stdlib/`, which is needed to build everything else — this is
why `make coldstart` must run before `make world`.

### Literate documentation (syncweb)

`docs/literate/OCaml.nw` (+ `OCaml_extra.nw`, `OCaml_native.nw`) is a Noweb
literate-programming book describing this codebase, kept in sync with the
real sources via `syncweb` (see `docs/literate/Makefile`, target `sync_c`
for the C side of `byterun/`, and the global CLAUDE.md conventions for `.nw`
markup). `SRC_ML`/`SRC_C` in that Makefile list exactly which source files
are woven into the book — check there before assuming a file is covered.
`docs/literate/lineage.txt`/`lineage.dot`/`lineage.pdf` trace the genealogy
of Caml/OCaml-family languages (rendered via the same pipeline used in
principia-softwarica).

### Plan 9 port

`config/plan9.h` + `Dockerfile.plan9` cross-compile `ocamlrun` (and
`otherlibs/unix`, `otherlibs/threads`) for Plan 9 using the `goken` image
and APE libs from the sibling `principia-softwarica` repo (symlinked here as
`principia`). This is a cross-compilation target only — it does not build
`ocamlc`/`ocamlopt` themselves.
